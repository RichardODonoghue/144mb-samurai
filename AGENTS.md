# AGENTS.md

## Project

144mb-samurai — a first-person samurai hack-and-slash game with raycasting, written as a competition entry for a 1,474,560-byte (post-decompression) game jam.

## Hard constraints

- **Size ceiling**: decompressed total < 1,474,560 bytes (executable + runtime only)
- **Format**: standalone Windows `.exe` — no web browsers, no browser-based runtimes
- **Language**: primary = assembly (NASM, Intel syntax), secondary = C where strictly needed
- **Dependencies**: avoid libraries and APIs wherever possible; roll your own
- **Originality**: all code/assets must be produced after competition open date

## Build system

- **Build command**: `build.bat` (calls vcvars64 internally, then NASM → link)
- **Toolchain**: NASM → MSVC `link.exe` (C files via `cl.exe` when needed)
- **Environment setup**: `build.bat` handles vcvars64 automatically. If running commands manually:
  `"C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"`
- **NASM path** (not on PATH by default): `C:\Users\richard\AppData\Local\bin\NASM\nasm.exe`
- **Link flags**: `/SUBSYSTEM:WINDOWS /ENTRY:main /NODEFAULTLIB /LARGEADDRESSAWARE:NO` — required. Without `/LARGEADDRESSAWARE:NO`, NASM's 32-bit `.data`/`.bss` relocations cause linker errors.
- **Libs**: `kernel32.lib user32.lib gdi32.lib` (no CRT)

## Source module structure

`src/main.asm` is the single entry point that `%include`s everything. `build.bat` assembles ONLY `src/main.asm`. All Win32 `extern` declarations live in `main.asm`.

### Include order (strict dependency chain)

```
src/main.asm
  ├─ %include "src/build.inc"    ← all equates, no dependencies
  ├─ extern declarations          ← all Win32 API imports
  ├─ %include "src/data.asm"     ← .data + .bss (must come before code)
  │    └─ %include "src/sin_table.inc"   ← 256-entry float sin/cos tables
  ├─ %include "src/init.asm"     ← depends on data.asm
  ├─ %include "src/render.asm"   ← depends on data.asm
  ├─ %include "src/input.asm"    ← depends on data.asm
  └─ %include "src/wndproc.asm"  ← depends on data.asm
```

### Module descriptions

| File | Lines | Purpose |
|------|-------|---------|
| `build.inc` | 72 | All `equ` constants: screen dims, Win32 constants, virtual keys, BMP offsets, stack frame layout |
| `data.asm` | 65 | `.data` section (strings, map, constants, sin/cos tables) and `.bss` section (player state, globals, DIB buffer) |
| `sin_table.inc` | 67 | Precomputed `sin_table` and `cos_table` (256 × 32-bit float each) generated by Python at `py -3` |
| `init.asm` | 106 | `init_palette` (fills 256-colour palette) and `init_dib` (creates 320×200 8-bit DIB via `CreateDIBSection`) |
| `render.asm` | 254 | `render_frame` — clears framebuffer, then DDA raycasts all 320 columns into `g_bits` using SSE2 floats + sin/cos tables |
| `input.asm` | 196 | `process_input` — polls WASD/Shift/Escape via `GetAsyncKeyState`, mouse look via `GetCursorPos`, collision detection against `world_map` |
| `wndproc.asm` | 62 | `wndproc` — handles `WM_DESTROY`/`WM_CLOSE`/`WM_PAINT`, stretches DIB to window via `StretchDIBits` |
| `main.asm` | 164 | Entry point `main` (window creation, init) + `game_loop` (PeekMessage → dispatch → render) |

### Data flow

```
input.asm                     render.asm                  wndproc.asm
─────────                     ──────────                  ───────────
reads:  player_angle,         reads:  player_x,            reads: g_bits,
        player_x, player_y,           player_y,                    g_bmi, g_hwnd
        world_map                     player_angle,
                                      g_bits, world_map
writes: player_x, player_y,   writes: g_bits[]            (read-only)
        player_angle,                 (framebuffer pixels)
        player_angle_f
```

Global state lives in `.bss` (`data.asm`):
- `player_x`, `player_y` (float) — position
- `player_angle` (byte 0-255) — direction index
- `player_angle_f` (float) — accumulated angle for smooth mouse
- `player_paused` (byte) — pause state
- `g_hwnd`, `g_hinst`, `g_dib`, `g_bits` — Win32 handles/pointers
- `g_bmi` (1064 bytes) — BITMAPINFO structure
- `prev_escape`, `prev_mouse_x/y`, `mouse_init` — input state

## Calling convention gotchas (x64 Windows)

- **Shadow space**: every `call` needs 32 bytes at `[rsp+0..rsp+1F]` for callee use
- **Stack alignment**: RSP must be **16-byte aligned** at each `call` instruction. At function entry RSP ≡ 8 mod 16 (return addr pushed). Adjust `sub rsp, N` so that (entry_offset + N) ≡ 8 mod 16.
- **Callee-saved**: RBX, RBP, RDI, RSI, R12-R15, XMM6-XMM15. Save before use.
- **Volatile**: RAX, RCX, RDX, R8-R11, XMM0-XMM5. Must assume clobbered after any `call`.
- **No memory-to-memory moves**: x86-64 does not allow `mov [mem], [mem]`. Use a register.
- **`DEFAULT REL`** is set in `build.inc` — all `[label]` accesses implicitly RIP-relative.

## Palette layout (8-bit indexed)

| Range | Contents |
|-------|----------|
| 0-95 | Sky gradient (dark purple → bright purple, R=B=30..220, G=0) |
| 96-103 | Brick (dark red → bright red) |
| 104-111 | Stone (dark grey → white) |
| 112-119 | Wood (dark brown → light brown) |
| 120-255 | Black (unused) |

Wall colour formula: `base = 96 + (wallType - 1) * 8`, X-side = base, Y-side = base+4 (darker).

## Known issues

- **WASD movement not working** — `GetAsyncKeyState` detection succeeds in input.asm (mouse look works, proving the function is called), but the collision/position-update path has an unresolved bug. To fix: trace execution from forced-movement add at `.not_a` through collision to `[player_x]` store.
- **Mouse hits screen edge** — relative tracking works but cursor can leave the window. Future: `SetCursorPos` recentering floods the message queue; use a budgeted PeekMessage drain to handle this.
- **No distance wall shading** — walls use flat per-type colours. Add shade-index modulation based on `perpWallDist`.
- **No floor/ceiling rendering** — currently solid colours.
